Tinyproxy is a light-weight HTTP proxy daemon designed for minimal resource consumption. It binds to a TCP port, handles HTTP and HTTPS proxy requests, and — once running — responds to POSIX signals for live reloading and graceful shutdown. This page covers every command-line flag, the full set of supported signals, default file paths, and the built-in statistics endpoint.

## Synopsis

```bash
tinyproxy [-vdch] [-c config-file] [-n fd]
```

## Command-Line Flags

<ParamField query="-c <config-file>" type="string">
  Use an alternate configuration file instead of the compiled-in default at `/etc/tinyproxy/tinyproxy.conf`. The path is read immediately at startup and re-read on `SIGUSR1`.
</ParamField>

<ParamField query="-d" type="flag">
  Do not daemonize. Tinyproxy stays in the foreground and writes log output to the terminal rather than a log file. Useful during development and for container environments that expect a foreground process.
</ParamField>

<ParamField query="-n <file-descriptor>" type="integer">
  After initialization is complete, write a newline character to the open file descriptor specified and then close it. This is the standard mechanism for notifying a service supervisor (such as s6 or runit) that Tinyproxy is up and ready to accept connections.
</ParamField>

<ParamField query="-h" type="flag">
  Display a short help screen listing all available command-line flags and exit immediately.
</ParamField>

<ParamField query="-v" type="flag">
  Display version information and exit immediately. No proxy is started.
</ParamField>

## Signals

In addition to command-line flags, Tinyproxy responds to several POSIX signals while running. Signals can be delivered with `kill(1)` using the PID written to the `PidFile`.

| Signal | Effect |
|--------|--------|
| `SIGHUP` | Force Tinyproxy to perform a garbage collection pass on the current connections linked list. This is normally done automatically after a certain number of connections, but can be triggered manually. **Daemon mode only.** |
| `SIGUSR1` | Force an immediate reload of the configuration file and the filter list. Active connections are not dropped, making this the preferred way to apply configuration changes to a running Tinyproxy instance, including foreground (`-d`) deployments. |
| `SIGTERM` | Initiate a graceful shutdown. Tinyproxy stops accepting new connections and exits cleanly once in-flight work is completed. |
| `SIGINT` | Same effect as `SIGTERM` — initiates a graceful shutdown. Typically generated by pressing `Ctrl+C` when running in foreground mode with `-d`. |

## Default File Paths

The locations below are compiled into the binary and used when no override is provided on the command line or in the configuration file.

| File | Default Path |
|------|--------------|
| Configuration file | `/etc/tinyproxy/tinyproxy.conf` |
| PID file | `/run/tinyproxy/tinyproxy.pid` |
| Log file | `/var/log/tinyproxy/tinyproxy.log` |

The PID file path can be overridden with the [`PidFile`](/reference/configuration-options#logging) directive. The log file path can be overridden with [`LogFile`](/reference/configuration-options#logging). Neither file is created unless the corresponding directive is present in the configuration.

## StatHost

Tinyproxy includes a built-in statistics endpoint. When it receives an HTTP request destined for the **stat host**, it intercepts the request and returns an internal page showing current connection statistics instead of forwarding the request upstream.

The default stat host name is `tinyproxy.stats`. You can change it at runtime using the `StatHost` configuration directive, and you can supply a custom HTML template for the statistics page using `StatFile`. If no `StatFile` is configured, Tinyproxy returns a minimal hard-coded statistics page.

To view the statistics page, configure your browser to use Tinyproxy as its proxy and then navigate to:

```
http://tinyproxy.stats/
```

## Example Usage

Start Tinyproxy with an explicit configuration file path:

```bash
tinyproxy -c /etc/tinyproxy/tinyproxy.conf
```

Run in the foreground for debugging:

```bash
tinyproxy -d -c /etc/tinyproxy/tinyproxy.conf
```

Send a live configuration reload to a running daemon:

```bash
kill -SIGUSR1 $(cat /run/tinyproxy/tinyproxy.pid)
```
